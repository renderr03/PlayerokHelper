# Подготовка стабильного выпуска 0.5.0

По указанию владельца до 25 ноября 2026, 14:00 Europe/Moscow не создавать GitHub Release, стабильный тег или перенос беты в `main`. Сейчас исходники хранятся в `beta/v0.5.0`, версия пакета `0.5.0b1`. Последний стабильный релиз — v0.4.1. Проверка и выпуск назначены отдельной задачей; если остаются блокирующие ошибки, публикацию остановить и сообщить владельцу.

## Проверки

1. Прочитать изменения беты и [инструкцию](BETA-0.5.0.md), проверить рабочую копию и новые коммиты `main`/бета-ветки. Сохранить изменения пользователя, не перезаписывать чужие коммиты.
2. Проверить обратную совместимость SQLite и старых KOSell/склад/аренда/бонусы. Бета добавляет таблицы; существующие таблицы не пересоздаются.
3. Не менять `updater_worker.py`, `service.py` и протокол 1 без отдельной обоснованной необходимости: установленный root-помощник v0.3.0 не заменяется обновлением кнопкой.
4. Изменить `pyproject.toml` и `shopbot.__version__` с `0.5.0b1` на `0.5.0`. В бете кнопка обновления отключена по версии; при стабильном номере она снова использует прежний механизм. Установки самой беты обновляются вручную, поскольку старый системный помощник принимает только стабильные версии и `main`.
5. Обновить README, CHANGELOG, отчёт `docs/releases/v0.5.0.md` и инструкцию перехода. Архивный отчёт беты сохранить как историю. Не представлять пресеты Twiboost/Vexboost как доказанную живую совместимость. Все провайдеры первоначально выключены, новый лот на паузе.
6. Выполнить `ruff check src tests`, `ruff format --check src tests`, `bash -n install.sh start.sh`, `pytest -q`, собрать wheel с обычной build isolation, проверить версию, импорты, новые модули и SQL в пакете. Тесты systemd требуют Linux с доступом к локальным Unix-сокетам. На этапе беты локально проходят 174 теста.
7. Перенести проверенные изменения в `main` без принудительной перезаписи; дождаться GitHub CI на Python 3.11 и 3.12 для точного итогового коммита.
8. Только после успешных проверок создать стабильный тег и GitHub Release v0.5.0 на этот коммит. Описание сделать коротким обычным русским текстом без `##` и `**`, а подробности вынести в отчёт по ссылке.
9. Проверить опубликованный тег, `draft=false`, `prerelease=false`, ссылку и неизменность прежних релизов. Сообщить владельцу результат.

## Что должно сохраниться

- Нельзя повторять создание закупки после таймаута, неизвестного ответа или прерывания. Неизвестное списание без номера удерживает новые закупки поставщика до сверки.
- Подтверждение получателя привязано к покупателю, чату и снимку параметров. Свежая проверка оплаты и лимитов обязательна перед запросом.
- Split: `paid` не равен доставке, нужен `completed` и время доставки. В этой бете используются оплачиваемые балансы, не seed-фраза кошелька.
- SMM: частичное выполнение требует сверки. Автовозврат выключен по умолчанию и разрешён только при окончательной отмене без выполнения и затрат. Возврат поставщика и возврат Playerok независимы.
- Учёт сохраняет исходную валюту и курс. Возврат выручки не стирает закупку. Справочный возврат поставщика повторно из затрат не вычитается.
- Не выполнять реальные закупки, возвраты, сообщения покупателям и развёртывание на сервере владельца в ходе автоматического выпуска. Не заявлять живую приёмку, если её не было.
- Ссылки автора сохраняются: [Boosty](https://boosty.to/renderr03/donate) и [ExpressHost](https://t.me/ExpressHost_Bot?start=ref_ASqRPBNS).
