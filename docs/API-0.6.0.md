# API и границы 0.6.0

Проверены публичные контракты и локальные подменённые ответы. Живые закупки, возвраты и изменение реальных лотов при разработке не выполнялись.

## Playerok

Чтение своих товаров: существующий GraphQL-документ `items`, фильтр `userId`, курсорная пагинация `first/after`; владелец результата дополнительно сверяется. Ориентиры: [Item search](https://github.com/th1ks/PlayerokAPI/blob/develop/PlayerokAPI/methods/items.py) и уже включённый документ проекта. Не выполняется HTTP-запрос по произвольной пользовательской ссылке.

Операция обновления товара описана в сторонних адаптерах, например [Playerok Universal account](https://github.com/alleexxeeyy/playerok-universal/blob/main/playerokapi/account.py). Наличие чужого кода не подтверждает работоспособность нашего контракта записи. В 0.6.0 изменение цены через API выключено; доступен расчёт рекомендации.

## KOSell

Первичный источник: [OpenAPI](https://ru.kosell.store/api/openapi.json), получен при разработке 0.6.0.

- GET `/api/v1/account/balance`: независимые balance_rub / balance_usd. USD — до четырёх десятичных знаков.
- POST `/api/v1/rental/calculate-price` и `/calculate-extend-price`: total_rub и total_usd без списания.
- POST `/api/v1/rental/rent`: currency RUB или USD, Idempotency-Key на операцию, тот же ключ при восстановлении ответа.
- POST `/api/v1/rental/{rental_uid}/extend`: currency RUB или USD. Контракт не даёт основания для слепого повтора неопределённого списания.
- RentalInfo.price_paid — записанные расходы USD; price_rub — расходы RUB при наличии. Для аренды учитываются currency_used и исходный запрос.
- ExtendResponse.price_paid интерпретируется в currency из ответа, которая сверяется с выбранным кошельком.

Для USD сохраняется фактическая нативная сумма. Рублёвый эквивалент использует котировку и помечается оценочным. API не даёт атомарного максимального лимита: он проверяется перед оплатой, а превышение фактической оценки после операции переводит лот в ручную паузу. Базовые ограничения проекта сохраняются.

## Схема и обновление

Добавлены таблицы shop_templates, customer_notes, automation_rules, kosell_charges. Существующие таблицы, ключ шифрования, личные файлы, service.py, updater_worker.py и протокол 1 не переписываются. Новые таблицы создаются при открытии базы после резервной копии установщиком обновления. Изоляция нескольких магазинов не реализуется в этой версии.
