# Telegram Stars и SMM · PlayerokHelper 0.5.0

Stars выдаются через партнёрский API Split с балансом TON/USDT. SMM использует API v2 и услуги Default; доступны преднастройки Twiboost, Vexboost и JustAnotherPanel. Преднастройка адреса не подтверждает живую совместимость конкретного аккаунта. Контракты изучены по [Split OpenAPI](https://api.split.tg/openapi.json) и [документации API v2](https://justanotherpanel.com/api).

Перед настройкой [подключите Playerok](CONNECTIONS.md). Ключи поставщиков принимаются только в формах личного чата администратора. Поставщик первоначально выключен, новый лот на паузе. Настройка ключа сама не разрешает реальные закупки.

## Настройка поставщика

Основной способ: «Подключения» → нужный поставщик → ввод ключа в личном чате администратора. Ключи сохраняются зашифрованно; сообщения с ними удаляются по возможности. Консольный вариант поддерживается для обслуживания:

```bash
.venv/bin/playerokhelper provider-setup --preset split
.venv/bin/playerokhelper provider-setup --preset twiboost
```

Для других преднастроек используйте `vexboost` или `jap`. Ключ вводится скрыто; передавать его аргументом команды не требуется. Вместо консоли можно использовать специальную форму личного чата администратора. Он сохраняется в SQLite с тем же шифрованием, что и склад. Смена ключа отключает поставщика и требует новой проверки. При незавершённых или спорных закупках смена ключа блокируется до сверки.

В Telegram откройте «Плагины → Telegram Stars» либо «SMM-услуги», затем поставщика:

1. Нажмите «Проверить подключение». Проверка читает баланс, а у SMM ещё и каталог. Она не создаёт тестовый платный заказ и не подтверждает доступность всех операций.
2. Сверьте отображаемые суммы с кабинетом, включая единицы TON/USDT. Адаптер Split использует nano-единицы баланса из опубликованной схемы.
3. Для иностранной валюты задайте курс учёта: например `TON 250` означает 250 рублей за TON, `USD 90` — 90 рублей за USDT/USD. Это ваш учётный курс, не автоматически загружаемый рыночный курс. Он действует 24 часа; после истечения новые закупки блокируются до обновления. В заказе сохраняется курс, действовавший при его отправке.
4. При необходимости настройте пороги низкого баланса, сообщения, подтверждение получателя и автовозврат. Подтверждение первоначально включено, автовозврат выключен.
5. Нажмите «Запустить» и подтвердите включение реальных закупок. Поставщик включается отдельно от готовности Playerok и ручной паузы конкретного лота.

Для Split используется партнёрский токен и внутренний баланс; бот не запрашивает seed-фразу TON. Условия выдачи токена, верификации и доступа к оплате с баланса определяет Split. Оплата покупателя при этом проходит на Playerok; Telegram служит панелью продавца.

## Привязка лота

Откройте «Привязать лот» в нужном плагине либо `/bind` и выберите новый тип кнопкой. Нужен существующий лот Playerok с ручной выдачей, без параллельной выдачи других реквизитов.

- Укажите UUID, название и поставщика.
- Для SMM выберите услугу из каталога Default; типы Custom Comments, подписки и другие специальные услуги в 0.5.0 не поддерживаются.
- Задайте количество в одной покупке. Для SMM проверяются `min/max` каталога; цена рассчитывается по стандартному тарифу API v2 за 1000 единиц. Сверьте это правило с документацией выбранной панели.
- Для Stars выберите баланс TON или USDT. В учёте USDT нормализуется как `USD`.
- Установите положительные лимиты в исходной валюте и рублях. Для SMM перечислите разрешённые домены: например `t.me, vk.com`. Домен сопоставляется точно; поддомены и `www` добавляются отдельно.
- Добавьте инструкцию и подтвердите предпросмотр. Лот сохранится на паузе. После настройки и проверки сценария снимите её в карточке.

Количество берётся из привязки, а не из названия товара. Получение покупателем нескольких лотов не умножает количество автоматически. Одна сделка Playerok соответствует одной закупке настроенного объёма.

Ссылки покупателя должны использовать HTTPS и вести на конкретный путь разрешённого домена. Корневые страницы, данные авторизации в URL, нестандартные порты, фрагменты и подмена домена отклоняются. Бот не загружает эти страницы и не проверяет существование поста или соответствие типа ссылки услуге; корректность цели нужно подтвердить покупателю, а ограничения услуги определяются поставщиком.

## Команды покупателя в чате Playerok

| Команда | Действие |
| --- | --- |
| `@username` или HTTPS-ссылка | Данные для единственного ожидающего оплаченного заказа в этом чате |
| `!получатель НОМЕР данные` | Явный выбор заказа, если ожидающих несколько |
| `!подтвердить КОД` | Подтверждение получателя и количества; действует пять минут |
| `!заказ НОМЕР` | Состояние внешнего заказа; остаток выполнения, если поставщик его сообщает |

Данные и подтверждение привязаны к покупателю, чату и заказу. Новый получатель отменяет старый код. Изменение параметров лота, ключа, курса или настроек после предпросмотра требует новой проверки. Перед отправкой выполняются свежая проверка оплаты Playerok, проблемы, цены, баланса и лимитов. Отправленного поставщику получателя менять нельзя.

## Отслеживание и сверка

До оплачиваемого запроса сохраняется намерение с зашифрованным получателем и снимком настроек. Повтор запроса не выполняется после таймаута, 5xx, непонятного ответа или перезапуска посреди отправки. Параметр Split `transfer_id` не используется как недокументированная гарантия идемпотентности. Если номер заказа неизвестен, новые закупки этого поставщика приостанавливаются до сверки.

В «Заказах и сверке» можно:

- привязать найденный номер после проверки получателя, услуги и количества в кабинете; это не создаёт новую закупку;
- повторить проверку статуса существующего номера;
- запросить отмену либо восстановление SMM, если каталог услуги разрешает операцию; запрос сохраняется до отправки, повтор после неопределённого ответа запрещён;
- сверить чистые затраты и подтверждённый возврат поставщика с отдельным подтверждением, затем закрыть спорную закупку без повторного выполнения.

Запрос восстановления допускается один раз на заказ в 0.5.0. Его принятие не подтверждает выполнение восстановления; результат проверяется в кабинете поставщика. Отмена также не означает возврат денег. У Split оплаченный инвойс не считается доставкой: требуется статус `completed` и время фактической доставки. История инвойсов просматривается ограниченно, до 1000 последних записей за одну сверку; если запись не найдена, заказ остаётся на проверке без повторной покупки.

Лимиты проверяются до отправки. Если API поставщика не поддерживает атомарный предел цены, они не могут запретить более дорогое фактическое списание на его стороне. Когда полученная фактическая стоимость превышает лимит, лот приостанавливается, продавец получает уведомление, затраты сохраняются.

## Возвраты и отчёты

Возврат поставщика на закупочный баланс и возврат покупателю на Playerok — независимые операции. Автовозврат Playerok включается отдельно и допустим только для окончательно отменённого SMM-заказа с нулевой стоимостью и полным неисполненным количеством, при ещё оплаченной сделке без проблемы. После неизвестного результата возврата повтор блокируется.

Для Stars, таймаутов, частичного выполнения и спорных статусов автовозврат не запускается. При ручной сверке продавец указывает уже чистые затраты и справочно подтверждённую сумму возврата поставщика: она не вычитается повторно. Ручная сверка затрат сама не возвращает деньги покупателю.

Известные внешние затраты учитываются даже после возврата выручки Playerok. При активной или спорной внешней закупке отчёт помечается предварительным. Excel сохраняет десять листов; в «Сделках» добавлены номер и статус поставщика, исходная сумма, валюта, курс и справочный возврат. Старые KOSell, склад, аренда собственного пула и бонусы сохраняются.

## Проверка перед продажами

Для стабильной 0.5.0 выполнены тесты, линтер, форматирование, проверка shell-скриптов и сборка wheel; результаты — в [отчёте релиза](releases/v0.5.0.md). Автотесты проверяют подменённые HTTP и Telegram API, разграничение покупателей, устаревшие подтверждения, изменение цены/баланса, финансовые повторы, восстановление, частичное выполнение, возвраты, отчёты и формы. Живые подключения и платные сценарии не заявляются проверенными.

На своём аккаунте сначала сверить баланс/каталог/курс и предпросмотр без покупки. Затем провести один контролируемый заказ в рамках правил Playerok и выбранной услуги, проверить реальный номер, доставку и себестоимость. Не имитировать потерю сети на реальных платных запросах ради теста: для этого есть локальные сценарии. При неизвестном списании сначала сверить кабинет, а не создавать замену.
