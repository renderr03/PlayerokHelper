# Установка и настройка PlayerokHelper

Telegram-панель и автоматизация одного магазина Playerok: аренда KOSell, собственный склад, автоответы, управление лотами и Excel-аналитика.

Автоматические тесты используют подменённые ответы API. Перед автовыдачей нужно подключить собственные аккаунты и проверить скрытие/восстановление лота на своём магазине.

[← На главную](../README.md)

## Возможности

- Меню: автонастройки, профиль, аналитика, плагины, управление аккаунтом и помощь.
- Аренда KOSell после проверки оплаты; подготовка аккаунта, выдача реквизитов, Steam Guard и продление отдельным заказом.
- Зашифрованный FIFO-склад: одна строка — одна позиция, резерв за заказом, инструкция и необязательная себестоимость.
- Автоответы по ключевым фразам, приоритетам и отдельным настройкам лотов; приветствие, расписание, сообщения по событиям и напоминания.
- `!оператор`, уведомления администратору и ответ в чат из Telegram с предпросмотром.
- Скрытие при нулевом остатке, недостаточном балансе, превышении лимита или сбое KOSell. Восстановление после двух успешных проверок; ручная пауза сохраняется.
- Автоподнятие и повторное выставление с отдельным включением платных действий, лимитом операции и суточным бюджетом.
- Отчёты на десяти листах Excel, фильтры, ежедневный отчёт и ежедневные резервные копии.
- Устойчивость к повторам событий и перезапускам. Неопределённые отправки и списания вынесены на ручную сверку.

## Установка одной командой

На Linux с работающим systemd, Python 3.11+, `venv`, `git` и `curl`:

**Арендовать сервер рекомендую [здесь — ExpressHost](https://t.me/ExpressHost_Bot?start=ref_ASqRPBNS).** Реферальная ссылка автора. Для установки нужен сервер с указанными выше зависимостями и доступом root или sudo.

```bash
curl -fsSL https://raw.githubusercontent.com/renderr03/PlayerokHelper/main/install.sh | bash
```

Установщик скачает проект в `~/PlayerokHelper`, установит зависимости в отдельное окружение и **спросит токен Telegram-бота и ID администратора прямо в консоли**. Токен вводится скрыто. Ключ шифрования создаётся автоматически; при повторной установке настройки и ключ сохраняются. Затем установщик создаст службу `playerokhelper.service`, включит запуск при загрузке сервера и сразу запустит бота. При повторной установке служба перезапускается с обновлённым приложением. Значение токена не включается в команду, файл службы или историю shell.

После установки бот уже работает в фоне, закрытие SSH его не остановит. Проверить состояние и журнал:

```bash
systemctl status playerokhelper --no-pager
journalctl -u playerokhelper -f
```

Для управления службой нужны root или sudo. При установке от обычного пользователя sudo может запросить пароль. Бот работает от пользователя, запустившего установщик; настройки `.env` остаются доступны только ему. При сбое systemd повторяет запуск через 10 секунд и продолжает попытки до восстановления работы; причину повторяющихся сбоев можно увидеть в журнале.

```bash
sudo systemctl restart playerokhelper
sudo systemctl stop playerokhelper
sudo systemctl start playerokhelper
```

От root команды выполняются без `sudo`. Ручное `systemctl stop` не вызывает автоматического перезапуска. До настройки KOSell/Playerok и проверки скрытия лотов запускается Telegram-панель; закупка и автовыдача остаются заблокированы.

Для установки без systemd-службы (например, в контейнере или для локальной разработки):

```bash
curl -fsSL https://raw.githubusercontent.com/renderr03/PlayerokHelper/main/install.sh | SHOPBOT_AUTOSTART=0 bash
bash ~/PlayerokHelper/start.sh
```

Включить службу для уже установленного проекта можно без переустановки:

```bash
cd ~/PlayerokHelper
.venv/bin/playerokhelper install-service
```

Повторная настройка токена и ID:

```bash
cd ~/PlayerokHelper
.venv/bin/playerokhelper setup
```

Для настройки KOSell и сессии Playerok в консоли используйте `.venv/bin/playerokhelper setup --connections`. Изменения подключений применяются после перезапуска службы. Основные команды доступны как `playerokhelper`; старое имя `playerok-bot` также поддерживается.

На Ubuntu 24.04 / Debian 12 необходимые системные пакеты: `sudo apt-get install python3 python3-venv git curl`. Каталог установки можно изменить: `curl -fsSL https://raw.githubusercontent.com/renderr03/PlayerokHelper/main/install.sh | SHOPBOT_INSTALL_DIR="$HOME/another-folder" bash`.

Перед автоматической выдачей по-прежнему обязательна проверка скрытия и восстановления лота, описанная ниже. Установщик не выполняет её автоматически. Если на сервере не работает systemd или не хватает прав, установка службы завершается ошибкой и не сообщает об успешном автозапуске; настроенные файлы сохраняются.

## Обновление из Telegram · v0.3.0

Для стандартной установки из Git с systemd доступна команда **`/version`** и кнопка **«⬆️ Версия и обновления»** в главном меню. Бот проверяет стабильные релизы официального репозитория каждые 6 часов. При появлении новой версии администраторы получают сообщение с кнопкой. Вручную проверить можно кнопкой **«Проверить сейчас»**; запросы ограничены одним в минуту. Уведомления можно выключить, сохранив ручную проверку.

**Первый переход с v0.2.0:** один раз повторите команду установки из начала инструкции от того же пользователя сервера. При установке sudo может запросить пароль. Это устанавливает отдельную службу `playerokhelper-update.service`, наблюдатель `playerokhelper-update.path` и менеджер обновлений. Старые версии сами этот механизм не получают.

Дальнейшее обновление:

1. Откройте `/version` и прочитайте изменения.
2. Нажмите **«Обновить бота»**, затем **«Установить v…»**. Предложение действует 10 минут; отмена делает старую кнопку недействительной.
3. Бот продолжает работу, пока готовится отдельное окружение. Если загрузка или сборка не удалась, рабочая версия не переключается.
4. Менеджер останавливает службу, проверяет отсутствие другого процесса базы, сохраняет SQLite и `.env`, переключает код и окружение и запускает бот в режиме проверки.
5. До подтверждения запуска обработка заказов и изменение настроек заблокированы. Проверяются версия, PID службы и два свежих сигнала запуска после успешного обращения к Telegram. При успехе работа возобновляется; при неудаче восстанавливается прежняя версия и база.
6. Результат приходит в Telegram и сохраняется в журнале `/version`. Хранятся последние 10 записей, в меню показываются последние 5.

Настройки, ключ шифрования и склад не нужно вводить заново. Сборка использует ограничения зависимостей из выбранного релиза. Коммит фиксируется при проверке версии и повторно проверяется перед подготовкой: изменённый тег не устанавливается. Если проект изменён локально, используется другая ветка или релиз затрагивает приватные файлы, обновление останавливается.

Служба обновления устанавливается из консоли и переживает остановку бота. Операции с Git, pip, окружением и данными выполняются с UID/GID пользователя установки. Менеджер управляет только `playerokhelper.service`; его установленная копия не заменяется скачанным кодом во время обновления.

Технические файлы находятся в `.updates/` и исключены из Git: запрос, результат, сохранённые окружения и резервные копии. Они могут занимать дополнительное место на диске. Не удаляйте активное окружение или файлы незавершённого обновления.

**Ограничения:** обновление кнопкой предназначено для стандартной установки с systemd и веткой `main`. Для Docker, запуска без systemd, переноса проекта, смены Python или изменения самого менеджера может потребоваться установка через консоль. Если не удалось восстановить даже предыдущую версию, автоматизация остаётся приостановленной; менеджер пытается отправить отдельное сообщение и потребуется проверка сервера. Неработающие сеть или Telegram могут задержать уведомление.

Для диагностики:

```bash
systemctl status playerokhelper playerokhelper-update.path --no-pager
journalctl -u playerokhelper-update -n 50 --no-pager
```

Не запускайте обычный установщик параллельно с обновлением из Telegram. Подробный отчёт: [v0.3.0](releases/v0.3.0.md).

## Мастер запуска и новые функции v0.2.0

Откройте `/setup` в Telegram или кнопку **«🧙 Настроить магазин»**. Мастер показывает фактическое состояние подключения Playerok, выбранный источник товара, результат проверки скрытия/восстановления и привязанные лоты. Для собственного склада KOSell не требуется; если уже привязаны лоты KOSell, их подключение продолжает проверяться.

Ключи и сессию вводите на сервере, в каталоге установленного проекта:

```bash
.venv/bin/playerokhelper setup --connections
sudo systemctl restart playerokhelper
```

Не отправляйте токены, cookie и пароли в Telegram. После изменения файлов подключений нужен перезапуск. Кнопка проверки в мастере читает текущее состояние, но сама не включает автоматизацию и не выполняет живой тест лота.

Для обязательной проверки скрытия/восстановления сначала остановите службу. Используйте UUID **своего активного тестового лота**:

```bash
sudo systemctl stop playerokhelper
.venv/bin/playerokhelper verify-visibility --item UUID_ТЕСТОВОГО_ЛОТА --confirm-reversible-test
sudo systemctl start playerokhelper
```

После теста снова откройте `/setup`. При ошибке изучите результат до включения продаж. Для Docker используйте команды в разделе Docker; при ручном запуске остановите рабочий процесс и запустите его снова после проверки.

**Проверка сценария:** в карточке привязанного лота нажмите **«🧪 Проверить сценарий»**. Бот проверит статус и владельца лота, паузу, наличие, лимиты, баланс и расчёт цены. Для продления сначала выберите действующую аренду магазина; меню показывает до 20 последних подходящих аренд. Вместо реквизитов в примере сообщения используются заменители. Проверка не закупает, не продлевает, не резервирует склад, не получает пароли/Guard-коды и не отправляет сообщения покупателю. Она не останавливает независимую фоновую обработку реальных заказов. Результат не гарантирует будущую доступность: перед реальной выдачей условия проверяются заново.

Последняя успешная проверка отмечается в мастере в течение 60 секунд, пока настройки лота совпадают с проверенными. Повторная проверка нужна после изменения настроек или при изменении условий поставщика.

**Ранние предупреждения:** откройте **«Управление аккаунтом → 🚨 Ранние предупреждения»**. По умолчанию они включены: остаток склада ≤ 3 позиции, баланс примерно на ≤ 2 аренды каждого активного лота KOSell. Пороги можно менять от 0 до 10000 или выключить весь блок предупреждений. Это уведомления, а не изменение правил закупки и скрытия лотов.

Проверки выполняются раз в минуту; после выдачи со склада остаток проверяется также сразу. Для лотов на ручной паузе периодические предупреждения об остатке/балансе не формируются. Оценки аренд используют один общий баланс и **не суммируются**; для продлений оценка не строится. Недоступность API означает отсутствие актуальных данных, а не нулевой остаток или баланс. Сообщение о проблеме ранее настроенного подключения приходит после трёх неудачных проверок подряд, о восстановлении — после двух успешных. Состояние предупреждений хранится в базе: повторный запуск не создаёт дубли, новое уведомление приходит при новом возникновении проблемы.

## Ручная установка

Python 3.11+; проверено в этой среде на Python 3.12. Для сервера рекомендуется Linux.

```bash
python -m venv .venv
source .venv/bin/activate
pip install -c constraints.txt -e '.[dev]'
cp .env.example .env
mkdir -p secrets
chmod 700 secrets
playerok-bot keygen
```

Сохраните сгенерированный ключ в `STOCK_ENCRYPTION_KEY` файла `.env`. Сохраните отдельную копию ключа вне каталога резервных копий. **Повторная генерация ключа для существующей базы не расшифрует старые данные.**

Заполните локально:

| Настройка | Значение |
| --- | --- |
| `TELEGRAM_BOT_TOKEN` | Токен вашего бота BotFather |
| `ADMIN_IDS` | Telegram ID администраторов через запятую |
| `KOSELL_API_KEY` | Ключ вашего KOSell |
| `STOCK_ENCRYPTION_KEY` | Постоянный ключ Fernet |

Создайте `secrets/playerok.json`:

```json
{
  "cookie": "СЮДА_ПОЛНЫЙ_COOKIE_ВАШЕЙ_СЕССИИ",
  "user_agent": "СЮДА_USER_AGENT_ЭТОГО_ЖЕ_БРАУЗЕРА"
}
```

```bash
chmod 600 .env secrets/playerok.json
playerok-bot doctor
```

Сессия Playerok может зависеть от IP, User-Agent и срока cookies. Если площадка отклоняет сессию, обновите её через обычный вход на площадку с используемого сервера. Встроенного обхода проверок или автоматического входа нет. Секреты не нужно присылать в чат.

## Обязательная проверка перед работой

Встроены REST-маршруты Playerok `discontinue` и `republish`, описанные в Python-клиенте площадки. Их наличие в клиенте не заменяет проверку на вашем аккаунте.

Пока рабочий процесс остановлен, выберите **свой активный тестовый лот**, который можно временно снять с продажи. Если установлена служба, сначала выполните `sudo systemctl stop playerokhelper` (от root — без sudo):

```bash
playerok-bot verify-visibility --item UUID_ТЕСТОВОГО_ЛОТА --confirm-reversible-test
playerok-bot doctor
```

Первая команда действительно снимает указанный лот с продажи и возвращает его обратно, проверяет статусы и сохраняет доказательство для конкретного аккаунта и версии контракта. Покупки она не создаёт. Если восстановление не удалось, проверьте лот вручную. Без успешной проверки финансовая автоматизация и выдача заблокированы.

```bash
# Для установки со службой:
sudo systemctl start playerokhelper
# Для ручной установки без службы:
playerok-bot run
```

Панель Telegram доступна и при неготовом подключении, чтобы настроить магазин. Состояние видно через `/status`. Наличие команды «run» не означает успешную живую приёмку.

## Настройка в Telegram

1. Откройте `/start`, затем «Плагины» → «Привязать лот» или `/bind`.
2. Укажите UUID уже созданного лота **с ручной выдачей**. Выберите `kosell`, `extend` или `stock`. Встроенная выдача Playerok не должна параллельно отправлять другие данные.
3. Для KOSell укажите ID игры из каталога сервиса, часы и максимальную закупочную стоимость в рублях. Балансы RUB и USD не взаимозаменяемы.
4. Для склада откройте лот → «Загрузить склад». Принимается UTF-8 TXT или текст. Один товар на строку; необязательная первая строка `cost=12.50` задаёт себестоимость каждой позиции. Повторная загрузка добавляет новые позиции — не загружайте повторно те же уникальные ключи.
5. В «Автонастройках» включите нужные функции. Шаблоны, обычные автоответы, автоподтверждение выполнения и продвижение первоначально выключены.
6. В карточке лота включите автоподнятие/автовыставление. Платные действия требуют включения и обоих положительных лимитов в разделе продвижения. День бюджета определяется `TIMEZONE`.

Рабочие часы, суточный бюджет и ручной режим «вне сети» общие для магазина. Шаблоны, переключатели сообщений и правила автоответчика могут переопределяться для лота. Команды покупателя имеют приоритет перед обычными ответами.

Команды покупателя:

| Команда | Действие |
| --- | --- |
| `!помощь` | Список команд |
| `!аренды` | Выданные аренды этого покупателя |
| `!код НОМЕР` | Steam Guard для его активной аренды |
| `!срок НОМЕР` | Окончание аренды |
| `!продлить НОМЕР` | Выбрать аренду для следующего заказа продления на 30 минут |
| `!инструкция` | Инструкция последнего заказа в чате |
| `!оператор` | Вызов продавца и пауза обычных автоответов |

Если заказ продления уже оплачен, `!продлить` привязывает его к выбранной аренде той же игры. Один заказ означает одно продление. При отсутствии свободной подходящей аренды бот не списывает деньги.

## Отчёты, восстановление и ограничения

- `/report` выгружает Excel; `/report 2026-11-01 2026-11-22 module=kosell` задаёт период, обе даты включительно. Допустим также фильтр `item=UUID`.
- `/import` загружает доступную историю только для аналитики. Себестоимость старых заказов остаётся неизвестной. Новые заказы до границы первого запуска не запускают выдачу.
- Для прибыли задайте комиссию Playerok в аналитике. Отчёт помечается неполным при неизвестной себестоимости, комиссии или неопределённых расходах. Возврат выручки не возвращает затраты KOSell.
- Резервные копии создаются ежедневно в `data/backups`, сохраняются последние семь. Ручная копия: `playerok-bot backup`.
- Восстановление: остановите бот, сохраните текущую базу отдельно, скопируйте выбранную копию в `data/shop.sqlite`, уберите относящиеся к старой базе `-wal`/`-shm`, верните **тот же** ключ, запустите проверку и бот. Не копируйте файл живой SQLite вручную: используйте команду backup.
- Продление KOSell не документирует идемпотентность. После таймаута автоматический повтор заблокирован. В карточке заказа можно подтвердить фактическое продление и стоимость после проверки KOSell; дополнительного списания эта сверка не делает.
- При неизвестном результате отправки бот проверяет историю чата. Если отправку подтвердить нельзя, администратор может вручную повторить **те же** данные из списка отправок.
- У KOSell нет атомарного параметра максимальной цены. Лимит проверяется до закупки; при более дорогом фактическом списании лот ставится на ручную паузу и приходит уведомление.
- Проверка наличия раз в минуту не резервирует товар на стороне поставщика: наличие и баланс могут измениться после проверки. Уже оплаченный невыполненный заказ передаётся администратору; автоматических возвратов нет.
- Используется неофициальный интерфейс Playerok. Изменение контрактов, cookies или ограничений площадки может потребовать обновления адаптера. Проверка запуска намеренно не подменяет живой тест.

## Docker

Контейнер работает от UID/GID `10001`. Для этого варианта запуска дайте ему доступ к файлам сессии (последующие проверки выполняйте внутри контейнера):

```bash
sudo chown -R 10001:10001 secrets
docker compose build
docker compose run --rm bot playerok-bot doctor
docker compose run --rm bot playerok-bot verify-visibility --item UUID_ТЕСТОВОГО_ЛОТА --confirm-reversible-test
docker compose up -d
```

База хранится в именованном томе `shop-data`. `.env` остаётся у вас, `secrets/` монтируется только для чтения. Для повторной проверки видимости сначала остановите рабочий контейнер. Один каталог базы допускает один рабочий процесс.

## Проверки

```bash
pytest -q

ruff format --check src tests
```

Тесты используют локальную SQLite, подменённые API и Telegram-сессию без сети. Они проверяют финансовые повторы, восстановление, разграничение покупателей, бюджет, шифрование, Excel, резервные копии и прохождение Telegram-форм. Живая приёмка описана в [LIVE_VERIFICATION.md](LIVE_VERIFICATION.md).
