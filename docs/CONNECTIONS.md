# Подключение магазина кнопками

Доступно с 0.5.0. Стабильная установка использует ветку `main`. Установщик по-прежнему один раз запрашивает токен Telegram-бота и Telegram ID администратора. Дальше подключение магазина и поставщиков выполняется в личном чате с ботом.

## Playerok

С 0.5.4 используется `curl_cffi 0.17.0` с профилем Chrome 152 для TLS/HTTP-соединения. Подключение аккаунта, вход по почте и анонимная проверка работают через один транспорт. Библиотека `playerokapi` не используется. Обновление выполняется кнопкой **«Версия и обновления → Проверить сейчас → Обновить бота»**; существующая сессия сохраняется.

Это не полноценный браузер: JavaScript и CAPTCHA не выполняются, автоматического решения проверок нет. Даже с новым транспортом сайт может вернуть HTTP 403. Новые подключения по токену получают User-Agent Chrome 152; вручную введённый или сохранённый User-Agent остаётся точным значением вашей сессии. После обновления проверьте доступ и повторите подключение, если аккаунт ещё не добавлен.

1. Откройте главное меню и нажмите **«Добавить аккаунт Playerok»**. Для уже подключённого магазина: **«Подключения → Переподключить Playerok»**.
2. Выберите **«По почте»**, **«По токену»** или **«Полная сессия браузера»**.
3. После успешного входа бот покажет имя магазина. Нажмите **«Продолжить настройку»**.

### Вход по почте

Введите email существующего аккаунта Playerok, затем шесть цифр из письма. Пароль не запрашивается. Повторный запрос ограничен минутой, форма действует десять минут; после пяти попыток нужен новый запрос. «Назад», «Отменить» и выход в другой раздел прекращают ввод. После перезапуска бота код нужно запросить заново.

Используются операции `getEmailAuthCode(email)` и `checkEmailAuthCode(input: {email, code})`, обнаруженные в публичном веб-клиенте Playerok 25 ноября 2026. Сессия берётся из Cookie ответа и дополнительно проверяется чтением профиля. Это не официальный стабильный API. Живой вход при разработке не выполнялся.

Если сайт требует проверку браузера, второй фактор либо изменил контракт, бот не обходит проверку. Войдите самостоятельно на [Playerok](https://playerok.com/), затем используйте токен. Повторного автоматического запроса письма после ошибки нет.

### Если токен правильный, но подключение не проходит

Обновите бот до 0.5.4 или новее через «Версия и обновления → Проверить сейчас → Обновить бота», затем повторите ввод токена. В 0.5.0 был дефект: первая проверка могла завершаться HTTP 500 из-за отсутствия запроса профиля в серверном кэше Playerok. Он исправлен в 0.5.1; в 0.5.4 заменён сетевой транспорт. Ни один из этих пунктов не гарантирует снятия отказа площадки.

Если ошибка остаётся, новая версия разделяет причины: HTTP 401/неподтверждённая сессия, HTTP 403/отклонённый доступ, ограничение частоты, сеть и несовместимость формата API. Для диагностики можно сообщить текст новой ошибки, не присылая сам токен, Cookie, коды и заголовки авторизации.

### Полная сессия браузера

С 0.5.3 выберите «Добавить аккаунт Playerok → Полная сессия браузера». Форма принимает Cookie и User-Agent отдельно, без ручного JSON.

1. В своём браузере войдите на [playerok.com](https://playerok.com/) обычным способом. Если сайт показывает проверку, пройдите её самостоятельно.
2. На компьютере откройте инструменты разработчика браузера (обычно F12) → Network / Сеть. Выберите успешный запрос именно к `playerok.com`, затем Request Headers / Заголовки запроса.
3. Скопируйте значение `Cookie` из этого запроса и отправьте его на первом шаге формы. Можно с префиксом `Cookie:`. Копируйте только заголовок для Playerok, не все Cookie браузера или других сайтов.
4. Из того же запроса скопируйте `User-Agent` и отправьте на втором шаге. Можно с префиксом `User-Agent:`. Другие заголовки не добавляйте.
5. Бот проверит профиль перед сохранением. Временный ввод действует десять минут. Пока он не завершён, Cookie хранится в зашифрованном виде в состоянии формы; «Отменить» или переход по кнопке очищает его.

Защитные Cookie могут зависеть от IP и браузерного контекста. Сессия с телефона/ПК может не подходить VPS, даже если токен правильный. Для зависимой от сети сессии нужен обычный разрешённый доступ из сети размещения бота. Если получить такой доступ не удаётся, уточните у Playerok допустимый способ интеграции. Передача Cookie/User-Agent не гарантирует снятие HTTP 403. Автоматических решателей проверок, имитации браузерных отпечатков и ротации адресов в боте нет.

Cookie дают доступ к аккаунту. Вводите их только в личную форму своего бота; не присылайте в ChatGPT, GitHub issues, группы или скриншоты. Telegram-чат не имеет сквозного шифрования; сообщение бот удаляет по возможности.

### Проверить доступ сервера

В способах подключения или под ошибкой нажмите «Проверить доступ сервера». Проверка выполняется там, где запущен бот, а не на телефоне пользователя.

Бот делает GET главной страницы и безопасный запрос типа GraphQL `__typename`. Запросы не содержат токенов, Cookie или авторизации; даже Cookie, выставленные главной страницей, не передаются в запрос к API. Переходы по перенаправлениям отключены, тело читается с ограничением. Повторная проверка — раз в минуту, результат за это время используется повторно.

На экран и в сохранённый результат попадают только статусы, тип ответа и признаки страницы проверки, без текста ответа, заголовков или секретов. Этот текст можно отправить для диагностики без данных аккаунта.

- **API отвечает:** это подтверждает только анонимный запрос. Работоспособность сессии проверяется отдельно.
- **API возвращает 403:** анонимный запрос тоже отклонён. Это не определяет валидность токена и само по себе не доказывает блокировку IP.
- **HTML-проверка:** обнаружены признаки страницы защиты. Диагностика не проходит её автоматически.
- **Нет ответа:** нужно проверить сеть и доступ с хоста бота. Проверка не включает и не отключает работающую автоматизацию магазина.

### Как получить токен

1. Откройте [playerok.com](https://playerok.com/) в браузере и войдите в свой аккаунт.
2. На компьютере откройте инструменты разработчика браузера: обычно F12. Выберите **Application / Приложение → Storage / Хранилище → Cookies → https://playerok.com**. В Firefox: **Хранилище → Куки**.
3. Найдите Cookie с именем **`token`** и скопируйте его значение.
4. В личном чате бота выберите **«По токену»** и отправьте значение. Не публикуйте его в issue, группе, скриншотах или отчётах.

Если одной Cookie недостаточно, можно отправить полный заголовок Cookie либо JSON:

```json
{"cookie":"token=ВАШ_ТОКЕН; ДРУГИЕ_COOKIE=ЗНАЧЕНИЕ","user_agent":"USER_AGENT_ВАШЕГО_БРАУЗЕРА"}
```

Сессия может зависеть от IP и User-Agent. Токен, отклоняемый площадкой на сервере бота, не считается подключённым. Бот проверяет профиль перед сохранением. Не отправляйте логин/пароль, если форма запрашивает токен.

### Что происходит с данными

Новые сессии Playerok и API-ключи сохраняются в SQLite в шифрованном виде тем же ключом, что защищает склад. Копию базы необходимо хранить вместе с защищённой копией `.env`. Пароль Playerok, коды входа и ключи не выводятся в сообщениях, диагностическом архиве и журнале действий.

Ввод доступен только администраторам и только в личном чате. Сообщения с email, кодом, токеном и ключом бот пытается удалить; ошибка удаления не останавливает проверку. Переписка с Telegram-ботом проходит через Telegram и не является сквозным шифрованием. Доступ к сессии даёт доступ к магазину: защитите Telegram-аккаунт администратора и сервер.

Подключение применяется без перезапуска службы. Уже начатые запросы завершаются; активный итератор может закончить чтение через прежнюю сессию, которая закрывается при завершении процесса. Если у магазина уже есть лоты или заказы, нельзя подключить другой Playerok ID в ту же базу. Переподключение того же магазина сохраняет его данные и действующую проверку скрытия.

## Проверка скрытия тестового лота

Откройте **«Настроить магазин → Проверить скрытие тестового лота»** и отправьте обычную ссылку на свой активный товар — её можно скопировать через «Поделиться» на Playerok. С 0.5.5 поддерживаются ссылки с коротким кодом и названием; искать UUID вручную не нужно. Полный UUID тоже подходит. Используйте лот без активной сделки.

Бот найдёт товар через API, проверит владельца и активный статус и покажет название. Только после кнопки **«Проверить лот»** начнётся скрытие и восстановление. Подтверждение действует две минуты и связано с текущим выбором; после нового ввода прежняя кнопка становится недействительной. Ссылки на чужие сайты или профили не подходят. При ошибке можно исправить ссылку либо нажать «Назад»/«Отменить».

При обычной привязке лота также поддерживаются ссылка и полный UUID. Бот проверяет принадлежность товара вашему магазину; привязка сама по себе не скрывает и не публикует товар.

Бот проверит владельца и активный статус, кратко скроет лот, восстановит его и проверит статус и баланс. Покупки, поднятие за деньги и отправка сообщений покупателям не выполняются. Успех подтверждается только после полного восстановления без уменьшения баланса.

Если ответ на скрытие потерялся, бот всё равно проверяет состояние и восстанавливает лот. Намерение записывается до изменения; после перезапуска восстановление выполняется перед включением автоматизации. При неподтверждённом восстановлении автовыдача остаётся заблокированной. Проверьте лот на сайте и повторно откройте мастер. Истёкшую сессию можно заменить сессией того же магазина, затем бот повторит восстановление.

## KOSell, Split и SMM

В **«Подключениях»** выберите KOSell, Split или SMM-панель. Для SMM доступны Twiboost, Vexboost и JustAnotherPanel. Получите API-ключ в кабинете поставщика и отправьте его в форму. Seed-фразы и пароли не нужны.

KOSell проверяет баланс до сохранения. Для Split/SMM ключ сохраняется с выключенными закупками: откройте карточку поставщика, проверьте подключение, настройте курс учёта и лимиты, затем отдельно включите поставщика. Подробности — [инструкция Stars и SMM](EXTERNAL_SERVICES.md).

Нельзя менять ключ поставщика при незавершённой закупке или сверке; KOSell также блокирует смену во время действующей аренды. Это защищает учёт и обращения к уже выданным аккаунтам.

## Навигация

У каждой формы есть **«Назад»** и **«Отменить»**, включая ошибки ввода и загрузку склада. «Назад» в пошаговом мастере возвращает предыдущий шаг; «Отменить» очищает незавершённый ввод. Навигация не отменяет уже выполненную покупку, отправленное сообщение или сохранённую настройку. Перед действиями с подтверждением сохраняется предпросмотр.

Команды прежних версий поддерживаются для совместимости, но не нужны для работы через меню. Команды покупателей в чатах самого Playerok сохраняются: эта площадка не поддерживает Telegram-кнопки. Список — [в README](../README.md#команды-покупателя).

С 0.5.2 разделы, формы и ошибки ввода обновляются в одном окне. Если окно удалено, бот создаёт замену. Уведомления о заказах и сообщениях сохраняются отдельными карточками: их кнопки открывают панель, не стирая событие. Файлы отчётов также приходят отдельно. При перезапуске активное окно восстанавливается по нажатию кнопки существующего меню; переход из карточки создаёт новое окно при необходимости.

С 0.5.6 переход из свежего уведомления создаёт панель ниже него, если старое окно осталось выше в переписке. Затем все кнопки работают в этой новой панели; повторное нажатие из того же уведомления не создаёт дубликат. Основные действия выделены синим, подтверждение — зелёным, отмена/возврат — красным. Оттенки зависят от темы и версии Telegram.

## Консоль для обслуживания

Подробные команды установки, диагностики, Docker, восстановления и ручного теста находятся в [INSTALLATION.md](INSTALLATION.md) и [LIVE_VERIFICATION.md](LIVE_VERIFICATION.md).

Старые `.env` и `secrets/playerok.json` поддерживаются. Сохранённое через бота подключение имеет приоритет над ними, в том числе после перезапуска и при запуске консольной диагностики. Для возврата к файлам сначала остановите службу и удалите только нужную запись `playerok_session` или `kosell_token` из таблицы `settings` с помощью SQLite, сохранив резервную копию базы и ключа. Это служебная операция; не очищайте склад, заказы и ключ шифрования.


### Проверки подключения и восстановление тестового лота (0.5.7)

В разделе подключений кнопка «Проверить KOSell» получает баланс даже до выбора источника и привязки лота. Проверка ограничена 15 секундами; сохранённый ключ при ошибке не меняется. Результат остаётся в панели, повтор доступен кнопкой.

Тест кратко снимает ваш активный лот с продажи и восстанавливает его. Пока восстановление не подтверждено, автоматическая выдача отключена. Не запускайте новый тест: используйте «Проверить восстановление» в мастере или восстановите продажу вручную на Playerok и нажмите эту кнопку. После потерянного ответа бот сверяет статус, но не повторяет неопределённую операцию восстановления. При однозначном отказе API повтор восстановления возможен кнопкой. Проданные, заблокированные, удалённые и чужие товары автоматически не перевыставляются.

Если проблема осталась, скачайте новую диагностику. Она содержит этап восстановления, последний известный статус и безопасную категорию ошибки; токены, Cookie и сведения аккаунта в неё не включаются. Архивы старых версий этих сведений не содержат.
