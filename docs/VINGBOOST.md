# VingBoost для AutoSMM

VingBoost — SMM-панель, поставщик услуг для социальных сетей. Домен vingboost.ru перенаправляет на [vingboost.com](https://vingboost.com/). В 0.6.1 используется актуальный HTTPS-адрес `https://vingboost.com/api/v2`, без пересылки ключа через редиректы.

## Подключение в Telegram

1. Обновите PlayerokHelper до 0.6.1.
2. В кабинете VingBoost получите собственный API-ключ.
3. В боте откройте «Плагины → SMM-услуги → Подключить поставщика → VingBoost»; также доступно «Подключения → Подключить SMM-панель».
4. Введите ключ в личной форме. Сообщение с ним удаляется по возможности, ключ хранится зашифрованным. Бот автоматически читает баланс и каталог; при ошибке ключ остаётся сохранённым, а закупки выключены.
5. Откройте настройки поставщика: укажите лимиты, при необходимости курс для учёта валюты в рублях. Привяжите собственный лот Playerok к выбранной услуге, задайте количество и разрешённые домены ссылок. После настройки включите поставщика.

Валюта и баланс берутся из API аккаунта VingBoost, а не из рекламных цен сайта. Если API возвращает USD, применяется существующая настройка курса учёта и лимит в исходной валюте. Эти средства не связаны с кошельками KOSell.

## Совместимость

Используется POST с параметрами формы `key` и `action`:

- balance — баланс и валюта аккаунта;
- services — каталог, цена за 1000 единиц, минимальное/максимальное количество и разрешённые действия;
- add — service, link, quantity; получение номера заказа;
- status — order; Completed, In progress, Awaiting, Canceled, Partial, Fail;
- cancel и refill — order в единственном числе.

У VingBoost собственные имена типов задач. Разрешены простые типы `like`, `subscribe`, `dislike`, `repost`, `friend`, `retweet`, `follow`, `favorite` и совместимый `Default`, если он присутствует. Доступность конкретного типа зависит от возвращённого каталога. `subscribe` — тип услуги подписчиков; это не разрешение на интервальные/автоматические подписки.

Типы comment, like_to_comment, dislike_to_comment, vote, Custom Comments, Subscription и неизвестные варианты не показываются: наша форма не собирает их дополнительные параметры. Поддержка панели не означает поддержку всех её услуг.

Awaiting считается ожиданием выполнения. Fail, противоречивый Completed с ненулевым остатком, частичное выполнение и неизвестные статусы требуют сверки; они не обозначаются как успешная выдача.

Отмена и refill разрешены только при соответствующем флаге услуги и подходящем состоянии заказа. Для отмены проверяется `ok=true`, для refill — положительный номер заявки. Подтверждение запроса не считается доказательством возврата или выполнения. Потерянные ответы на создание заказа/отмену/refill не вызывают автоматический повтор.

## На чём основана интеграция

Изучены официальная главная страница, публично поставляемая страница разработчика приложения (`/developer`, модуль JS 79.43296ebf3.js) и справочник `panel.lang_pack.developer` из [публичной конфигурации сайта](https://vingboost.com/api?json). Справочник задаёт адрес API v2, параметры key/action, типы услуг, цену за 1000, состояния, баланс, order и примеры ответов cancel/refill.

Выполнен только анонимный запрос balance без ключа: GET и POST отвечают JSON HTTP 400 user_inactive. Это подтверждает доступность маршрута, но не действительность чужого ключа или успешность заказа. Авторизованные запросы с реальным ключом, покупки и возвраты при разработке не выполнялись. Качество, скорость и гарантии конкретных услуг поставщика не оценивались.

Локальные тесты подменяют API и проверяют документы, безопасный каталог, расчёт, параметры запросов, статусы, отмену/refill, отсутствие повторного списания, автоматическую проверку ключа и сохранность других поставщиков.
