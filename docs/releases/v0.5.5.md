# PlayerokHelper 0.5.5 · обычные ссылки на товары

В форме проверки тестового лота обычная ссылка Playerok с коротким кодом не содержала полного UUID. Бот отклонял её, а сообщение об ошибке совпадало с приглашением к вводу. Из-за редактирования одного окна сообщение визуально не менялось. Пользователь видел отсутствие реакции.

## Что исправлено

Теперь можно присылать обычные ссылки вида `https://playerok.com/products/короткий-код-название`, скопированные через «Поделиться». Точное имя товара из адреса передаётся в существующий GraphQL-контракт `item(slug: ...)`; полный UUID берётся из ответа API. Короткий код не дополняется до выдуманного UUID. Полные ID и прежние ссылки с UUID поддерживаются.

Форма сообщает о поиске, проверяет владельца и активный статус и показывает название товара перед подтверждением. Неверный формат, чужой или неактивный товар, отсутствие товара и ошибка API имеют разные сообщения. Ошибка ввода отличается от начального приглашения. Ответы обновляют прежнее окно, отмена и возврат доступны кнопками.

Привязка лотов также принимает обычную ссылку, получает ID через API и проверяет владельца. Скрытие, публикация, закупка или отправка покупателю при разборе ссылки не выполняются.

## Подтверждение и ограничения

Подтверждение проверки скрытия связано с текущим выбором, действует две минуты и используется один раз. Новый ввод, даже ошибочный, сбрасывает предыдущий выбор. Старая кнопка не может запустить проверку другого выбранного товара. Кнопки подтверждения прежних версий требуют повторного выбора.

Во время получения профиля и товара закрепляется один клиент, чтобы переподключение не смешало данные разных магазинов. Перед скрытием сохраняются прежние повторная проверка владельца/статуса и восстановление после неопределённого результата. Для проверки выбирайте свой активный тестовый товар без сделки.

Разбор адреса принимает только товарные ссылки Playerok и полный UUID. URL с другим доменом, учётными данными, нестандартным портом, путём профиля или вложенным путём отклоняются. По присланному URL нет отдельного HTTP-запроса, перенаправлений или загрузки HTML — используется фиксированный API Playerok.

## Проверки и обновление

Добавлены сценарии обычной ссылки с коротким кодом, прежнего UUID, параметров ссылки, владельца/статуса, отсутствующего товара, ошибок сети, видимого ответа в одном окне, старых/просроченных/повторных подтверждений и привязки лота. Тесты используют подменённый API, действия скрытия и восстановления выполняются только на тестовом клиенте. Реальный товар пользователя при разработке не изменялся.

Локально прошли 298 тестов, линтер, форматирование и проверка shell. Перед выпуском также проверяются сборка wheel и GitHub CI на Python 3.11/3.12. Схема базы и системный помощник протокола 1 не меняются; настройки и подключённый аккаунт сохраняются.

В Telegram откройте **«Версия и обновления → Проверить сейчас → Обновить бота»**. Затем заново откройте **«Настроить магазин → Проверить скрытие тестового лота»** и отправьте прежнюю ссылку. После определения товара бот покажет отдельную кнопку подтверждения. Искать UUID и работать с консолью не требуется.
