# PlayerokHelper 0.5.0 · 25 ноября 2026

Стабильный выпуск объединяет Stars через Split, SMM API v2 и настройку магазина кнопками. [GitHub Release](https://github.com/renderr03/PlayerokHelper/releases/tag/v0.5.0).

## Новые возможности

| Возможность | Что получает продавец |
| --- | --- |
| Добавление Playerok | Кнопка в главном меню, вход по почте с одноразовым кодом либо по токену, проверка профиля до сохранения |
| Подключения из Telegram | Playerok, KOSell, Split и три SMM-панели настраиваются в личном чате администратора, сессии и ключи зашифрованы в базе |
| Навигация | Действия доступны кнопками, в формах есть «Назад» и «Отменить», команды обслуживания перенесены в документацию |
| Тестовый лот | Проверка краткого скрытия и восстановления с подтверждением, сохранением намерения и восстановлением после сбоя |
| Telegram Stars | Split, TON/USDT-баланс, проверка получателя, подтверждение покупателем и сверка фактической доставки |
| SMM API v2 | Каталог услуг Default, количество и разрешённые домены по лоту, статусы, отмена/восстановление при поддержке услуги |

Для внешних закупок предусмотрены лимиты в исходной валюте и рублях, курс учёта с актуальностью 24 часа и уведомления о низком балансе. Неизвестное списание не повторяется: поставщик блокируется до сверки, найденный номер можно привязать без новой покупки. Частичное выполнение требует ручной сверки.

Excel сохраняет десять листов. В сделках отражаются валюта, курс, фактические затраты и внешний номер. Возврат поставщика сверяется отдельно от возврата покупателю Playerok; возврат выручки не стирает расходы.

## Настройка

1. Откройте меню бота, нажмите «Добавить аккаунт Playerok» и выберите почту или токен.
2. В «Подключениях» добавьте нужного поставщика. Для своего склада поставщик не нужен.
3. В мастере настройте источник, проверьте свой тестовый лот и привяжите существующий лот Playerok.
4. Для Stars/SMM проверьте чтение API, баланс, каталог и курс учёта, задайте лимиты. Затем отдельно разрешите закупки у поставщика и снимите паузу лота.

Поставщики первоначально выключены, новые внешние лоты создаются на паузе. Ни ввод ключа, ни проверка баланса сами не запускают оплачиваемые заказы.

## Обновление существующей установки

Для стандартной установки v0.3.0/v0.4.x на `main` с системным менеджером откройте «Версия и обновления → Проверить сейчас → Обновить бота». Сначала подготавливаются код и окружение, затем создаётся копия базы и перезапускается служба. Проверка новых стабильных версий в фоне выполняется раз в шесть часов; мгновенную массовую рассылку выпуск не запускает.

Сохраняются `.env`, ключ шифрования, данные склада, заказы, собственные аренды и бонусы. Новые таблицы добавляются без пересоздания существующих. Повторно вводить действующие подключения не требуется: прежние файлы сессии и KOSell поддерживаются, настройки из панели имеют приоритет. Старые команды администратора остаются для совместимости, но не нужны при работе кнопками. Команды покупателей в чатах самого Playerok сохраняются.

Для Docker, ручного запуска и установленной беты используйте [порядок перехода](../UPGRADE-0.5.0.md). Старый системный помощник не принимает бета-номер версии; перейти с `0.5.0bN` на стабильную сборку его кнопкой нельзя.

Протокол системного обновления остаётся 1; `service.py` не меняется. В помощнике относительно v0.4.1 изменён только текст аварийного уведомления: вместо консольных команд — ссылка на GitHub. Установленная системная копия помощника не заменяется кнопочным обновлением, поэтому на старых установках этот редкий аварийный текст сохраняется до обычной переустановки помощника.

## Проверки и их границы

- Полный набор из 194 тестов прошёл на стабильной версии, включая KOSell, склад, собственные аренды, бонусы, отчёты и обновления.
- Новые тесты проверяют доступ администратора, запрет ввода ключей в группе, шифрование, отмену/возврат шага, ограничение попыток кода, Cookie ответа и безопасные ошибки API.
- Проверены незавершённые запросы при переподключении, запрет смешивания магазинов и смены KOSell при активной аренде или пришедшем во время проверки заказе.
- Проверены потерянные ответы и перезапуски, отсутствие повторной закупки, частичное выполнение, неоднозначные отмены/возвраты и восстановление тестового лота.
- Линтер, форматирование, проверка shell-скриптов и сборка wheel 0.5.0 проходят. Версия, импорты новых модулей, SQL и GraphQL-контракты проверены в установленном wheel.
- [GitHub CI](https://github.com/renderr03/PlayerokHelper/actions/workflows/tests.yml) проверяет итоговый коммит на Python 3.11 и 3.12; публикация допускается только после успеха обоих заданий.

Автотесты используют подменённые HTTP/Telegram API. Живые входы, письма с кодами, платные закупки, возвраты и сообщения покупателям при подготовке релиза не выполнялись. Вход по почте реализован по операциям публичного веб-клиента Playerok, изученным 25 ноября 2026. Если площадка требует проверку браузера, второй фактор или изменила контракт, используйте самостоятельный вход на сайте и токен. Защита площадки не обходится.

Split использует партнёрский токен и внутренний баланс; seed-фраза TON не требуется. Наличие пресета Twiboost/Vexboost/JustAnotherPanel не подтверждает совместимость конкретного аккаунта или услуги: перед продажами сверяйте кабинет, баланс, каталог и предпросмотр. Реальное выполнение и цену определяет поставщик. Лимит бота не является атомарной гарантией цены на стороне API, если такой гарантии у поставщика нет.

Telegram-чат не имеет сквозного шифрования. Секреты вводятся только в предназначенные для них формы личного чата администратора. Бот удаляет входящие сообщения с ними по возможности; сохранённые ключи и сессии шифруются ключом установки.
