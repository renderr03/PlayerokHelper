# PlayerokHelper 0.5.1 · исправление подключения

В 0.5.0 правильный токен мог не пройти первичную проверку из-за ошибки обработки серверного кэша GraphQL. Пользователь видел общую фразу «Playerok или поставщик не подтвердил подключение», которая не позволяла отличить дефект запроса от отказа авторизации.

## Причина и исправление

Запросы чтения сначала отправляются с хешем документа. Если сервер не знает хеш, он отвечает `PERSISTED_QUERY_NOT_FOUND`. Адаптер обрабатывал этот ответ только при HTTP 200. На реальном публичном API Playerok анонимная проверка неизвестного хеша вернула HTTP 500 с тем же кодом; полный запрос чтения принимался с HTTP 200.

Теперь известный ответ об отсутствии хеша обрабатывается при HTTP 200, 400 и 500. Полный документ отправляется POST один раз, только для чтения. Неизвестный серверный сбой, запреты доступа, HTTP 429 и неоднозначный смешанный ответ не запускают повтор. Оплачиваемые операции и прочие мутации по-прежнему не повторяются автоматически.

Сообщения подключения отдельно описывают неподтверждённую сессию, HTTP 403, ограничение запросов, сетевой сбой и ошибку совместимости запроса. Они формируются по разрешённым категориям ошибок, не содержат токенов и необработанных ответов API. Данные подключения сохраняются только после подтверждённого профиля.

## Обновление

Откройте «Версия и обновления → Проверить сейчас → Обновить бота». После запуска 0.5.1 повторите добавление аккаунта. Если ошибка сохранится, сообщите её новый текст без токена и Cookie: дефект кэша не исключает независимый отказ сессии или доступа с сервера.

Склад, заказы, ключ шифрования и сохранённые подключения не меняются. Системный помощник, `service.py` и протокол обновления 1 не изменены относительно 0.5.0.

## Проверки

- 216 тестов: существующие продажи, аренды, Stars/SMM, обновления и новые сценарии подключения.
- HTTP 200/400/500 с двумя форматами ответа об отсутствии хеша; успешный ввод токена через меню после HTTP 500.
- Отсутствие повторов при иных 5xx, HTTP 401/403/429, смешанных и некорректных ответах; отсутствие повтора мутации даже при сообщении о кэше.
- Раздельные безопасные сообщения об ошибках, сохранённые кнопки отмены и отсутствие токена в ответах.
- Линтер, форматирование, shell-скрипты и wheel проверяются перед выпуском. GitHub CI проверяет итоговый коммит на Python 3.11 и 3.12.

Проверка реального API выполнялась без авторизации и без аккаунта пользователя. После исправления анонимный запрос профиля завершился ожидаемым `playerok_auth_required`, а не ошибкой кэша. Подключение конкретного пользовательского токена, живой вход и платные операции при подготовке исправления не выполнялись.
