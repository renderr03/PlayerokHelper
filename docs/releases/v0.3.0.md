## Для тех, у кого уже установлен бот

**v0.2.0 и более ранние версии не получат механизм сами.** Один раз выполните обычную установку от прежнего пользователя сервера:

```bash
curl -fsSL https://raw.githubusercontent.com/renderr03/PlayerokHelper/main/install.sh | bash
```

Для нестандартного каталога сохраните прежний `SHOPBOT_INSTALL_DIR`. Настройки и ключ шифрования сохраняются. Установщик добавит менеджер systemd и наблюдатель запросов. Затем откройте `/version` в Telegram. После установки v0.3.0 следующие совместимые стабильные версии доступны кнопкой.

Для новой установки команда та же. Docker и ручной запуск сохраняют обычный способ обновления; проверка новых версий доступна и там.

## Как проходит обновление

1. Бот фиксирует версию и точный коммит релиза; предрелизы не предлагаются.
2. Отдельный менеджер проверяет Git-установку и собирает новое окружение, сохраняя работу текущего бота.
3. После подготовки служба останавливается, блокировка базы проверяется, SQLite и `.env` копируются.
4. Код переключается только вперёд по истории `main`, а `.venv` указывает на подготовленное окружение.
5. Новая версия запускается с приостановленными заказами и изменениями настроек. После успешной проверки Telegram должны поступить два свежих сигнала от PID службы с ожидаемой версией.
6. При успехе работа продолжается. При ошибке запуска возвращаются прежний код, окружение и данные; результат приходит в Telegram.

Режим проверки не закупает и не выдаёт товар. Существующие правила работы с неопределёнными операциями сохраняются: после подтверждения запуска выполняется штатное восстановление обработчика.

## Практические границы

Управление systemd в сценариях обновления проверено через тестовый интерфейс, синтаксис файлов — через `systemd-analyze`. Реальное обновление пользовательского сервера, реальные закупки и списания в рамках разработки не выполнялись. Проверка запуска подтверждает загрузку версии и связь с Telegram, а не исправность всех операций Playerok/KOSell.

Для кнопки нужна стандартная Git-установка с systemd. Локальные изменения сохраняются и блокируют установку. Если автоматическое восстановление не удаётся, обработка остаётся приостановленной и требуется проверка сервера. Технические окружения и резервные копии сохраняются в `.updates/`; нужно учитывать их место на диске.

Прежние функции, Boosty и рекомендация ExpressHost сохранены.
