# PlayerokHelper 0.5.0b2 · 25 ноября 2026

Бета для проверки перед стабильным выпуском, назначенным на 25 ноября в 14:00 МСК. Ветка: [`beta/v0.5.0`](https://github.com/renderr03/PlayerokHelper/tree/beta/v0.5.0). Стабильные `main`, теги и GitHub Release до этого времени не изменяются.

## Что изменилось

1. **Добавление Playerok:** отдельная кнопка в главном меню, выбор почты или токена. Одноразовый код без пароля, ограничение повторных запросов и числа попыток. Профиль проверяется до сохранения.
2. **Подключения в Telegram:** Playerok, KOSell, Split и три SMM-панели настраиваются в личном чате администратора. Новые сессии и ключи зашифрованы в SQLite, сообщения с секретами удаляются по возможности. Подключение применяется без перезапуска службы.
3. **Навигация:** «Назад» и «Отменить» доступны во всех формах, после ошибок и при загрузке склада. Мастера сохраняют до восьми предыдущих шагов в памяти; возврат восстанавливает ввод, не повторяет действие с API. Секретные формы в историю переходов не попадают.
4. **Проверка лота:** краткое скрытие и восстановление своего активного тестового лота с подтверждением. Намерение сохраняется до запроса; при потерянном ответе или перезапуске восстановление проверяется повторно. Неподтверждённое восстановление блокирует автоматизацию.
5. **Тексты:** в сообщениях панели больше нет требований вводить slash-команды или выполнять консольные команды. Помощь ведёт в нужные разделы; подробные команды остаются в документации. Старые команды сохранены для совместимости, команды покупателей на Playerok продолжают работать.
6. **Сохранность магазина:** переподключение не обрывает текущие запросы; другая учётная запись не может подменить магазин с заказами и лотами. Ключ KOSell нельзя заменить при незавершённой закупке, активной аренде или спорном списании, включая заказ, пришедший во время проверки нового ключа.

## Границы проверки и совместимость

Вход по почте реализован по операциям публичного веб-клиента Playerok, изученным 25 ноября: `getEmailAuthCode` и `checkEmailAuthCode`. При разработке не отправлялись реальные письма/коды и не использовались чужие сессии. Живая приёмка входа и платных интеграций не заявляется. Проверка браузера или второй фактор не обходятся: пользователь может войти на сайте и использовать собственный токен.

Telegram-чат не имеет сквозного шифрования. Секреты принимаются только в предусмотренных формах личного чата администратора. Хранимые данные защищаются прежним ключом установки, который нельзя терять или менять вместе с обновлением.

Протокол обновления 1, структура служебных запросов, права root-помощника и `service.py` сохранены. В `updater_worker.notify_failure` изменён только текст аварийного уведомления: консольные команды заменены ссылкой на инструкцию. Эта правка действует для новых установок помощника; его ранее установленная системная копия не заменяется обновлением кнопкой и сохраняет старый аварийный текст до обычной переустановки. Работающая панель использует новые тексты сразу.

Сессия и ключи из прежних файлов поддерживаются. Приоритет настроек, сохранённых в панели, описан в [инструкции подключений](../CONNECTIONS.md). Переход с самой беты на стабильную версию остаётся ручным из-за ограничений ранее установленного помощника; стабильные установки v0.3.0/v0.4.x сохраняют штатную кнопку обновления.
