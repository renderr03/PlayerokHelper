### Где искать

- `/setup` или кнопка **«🧙 Настроить магазин»** в главном меню.
- **«Управление аккаунтом → 🚨 Ранние предупреждения»**; тот же пункт доступен в автонастройках.
- **Карточка лота → 🧪 Проверить сценарий**. Для продления сначала выбирается действующая аренда магазина.

### Настройки по умолчанию

Предупреждения включены. Порог склада — **3 позиции**, порог баланса — примерно **2 аренды** для каждого активного лота KOSell. Пороги настраиваются в Telegram. Баланс общий: оценки разных лотов не складываются. Для продлений оценка количества аренд не строится.

Сбой настроенного подключения требует трёх неудачных проверок подряд; восстановление — двух успешных. Проверки выполняются раз в минуту. Состояние хранится в SQLite, поэтому перезапуск не создаёт дубли. Существующие действия при отсутствии товара и недостаточном балансе продолжают работать независимо от предупреждений.

## Как обновиться

Выполняйте обновление от того же пользователя сервера, который устанавливал бот. Перед обновлением создайте резервную копию:

```bash
cd ~/PlayerokHelper
.venv/bin/playerokhelper backup
curl -fsSL https://raw.githubusercontent.com/renderr03/PlayerokHelper/main/install.sh | bash
```

Если проект установлен в другой каталог, перейдите в него и передайте установщику прежний `SHOPBOT_INSTALL_DIR`. Установщик сохраняет существующие настройки и ключ шифрования, обновляет зависимости и перезапускает службу. При изменённых файлах проекта обновление остановится: сохраните свои изменения перед повтором.

После обновления:

1. Проверьте `systemctl status playerokhelper --no-pager`.
2. Откройте `/setup` в Telegram и проверьте состояние подключений.
3. При необходимости измените пороги предупреждений.
4. Откройте карточку лота и выполните проверку сценария.

Менять ключ шифрования и заново загружать склад не требуется. Новые настройки добавляются автоматически, прежний порог склада сохраняется. Для новых установок остаётся команда из README.

## Границы проверки

Автотесты используют подменённые API и Telegram-сессию. Реальные закупки, списания и работа с пользовательским магазином в рамках этой версии не выполнялись. Для своего магазина используйте [инструкцию живой проверки](../LIVE_VERIFICATION.md).

Проверка сценария не резервирует товар и не гарантирует цену следующей покупки. Получение реквизитов и Steam Guard в неё не входит. Она не меняет готовность автоматизации и не останавливает независимую фоновую обработку оплаченных заказов.

Если условия или API изменились, бот покажет ограничение либо отсутствие актуальных данных. Для неопределённых реальных операций сохраняется существующая ручная сверка.
