# PlayerokHelper 0.5.3 · диагностика HTTP 403 и полная сессия

После исправления кэша в 0.5.1 площадка всё ещё может отвечать HTTP 403 на проверку токена. Это другой отказ, который нельзя надёжно объяснить только неправильным токеном или только IP сервера.

## Подключение по шагам

Добавлена кнопка «Полная сессия браузера»: сначала Cookie, затем User-Agent одного браузерного запроса. Ручной JSON не нужен. Префиксы заголовков поддерживаются, управляющие символы и неверный формат отклоняются.

Промежуточный Cookie шифруется в состоянии формы, ввод действует десять минут. Навигация/отмена очищают незавершённые данные. Сессия сохраняется в базе только после подтверждённого профиля и проверки магазина. Если переданная сессия также получает 403, бот предлагает диагностику вместо слепого повтора того же токена.

Cookie могут зависеть от IP и браузерного контекста. Сессия с другого устройства не гарантирует работу на VPS. [Инструкция обычного подключения](../CONNECTIONS.md#полная-сессия-браузера) описывает, что копировать из своего браузера и почему иногда нужен разрешённый доступ из сети размещения.

## Анонимная проверка доступа

Кнопка «Проверить доступ сервера» выполняет два GET-запроса с хоста бота: главная страница и GraphQL `__typename`. Нет токенов, Cookie или входа в аккаунт; Cookie ответа главной страницы также очищаются перед запросом API. Нет перенаправлений или автоматических повторов, чтение тела ограничено 32 КиБ на адрес. Результат кэшируется на минуту.

Показываются статусы сайта/API, вид ответа и признаки HTML-страницы защиты. Исходные ответы и заголовки не попадают в текст диагностики или настройки. HTTP 200 на анонимном API не означает успешную авторизацию, а HTTP 403 без Cookie не доказывает блокировку IP или неправильный токен.

Работающая автоматизация не переключается по результатам анонимного теста. Отправка денег, покупок и сообщений покупателям не выполняется.

## Ошибки и ограничения

HTML 403 со следами страницы проверки/защиты получает отдельную категорию. JSON 403 не становится «страницей защиты» только из-за заголовка `Server`. Вход по почте, отклонённый HTTP 403, больше не описывается как неверный код из письма. Повторы защищённых запросов не добавлены.

Это диагностическое обновление, а не гарантия устранения отказа Playerok. Если обычный доступ с подходящей сети и сессия не принимаются, потребуется уточнение разрешённого способа подключения у площадки. Обход проверок браузера, решатели CAPTCHA, имитация отпечатков и ротация адресов не добавлялись.

## Проверки и обновление

Проверены 252 теста: анонимность запроса, удаление Cookie между адресами, запрет перенаправлений, безопасные сетевые ошибки, классификация HTML/JSON 403, пошаговый ввод с точным User-Agent, шифрование промежуточного Cookie, отмена, приватный чат, истёкший ввод, неверные заголовки, отказ без повторов и ограничение частоты диагностики. Сохраняются проверки аренды, склада, Stars/SMM, меню и обновления.

Перед выпуском выполняются линтер, форматирование, shell-проверки, сборка wheel и GitHub CI. Проверка анонимного доступа из рабочего окружения разработчика вернула HTTP 200 для сайта и API; это не результат проверки VPS пользователя. Его токен не использовался, живой вход и финансовые операции не выполнялись.

Стандартное обновление: «Версия и обновления → Проверить сейчас → Обновить бота». Затем откройте способы подключения и нажмите «Проверить доступ сервера». Можно прислать этот результат, не передавая Cookie или токен. Системный помощник и протокол 1 не меняются.
