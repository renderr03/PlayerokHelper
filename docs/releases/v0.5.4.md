# PlayerokHelper 0.5.4 · сетевой транспорт curl_cffi

Подключение Playerok переведено на `curl_cffi 0.17.0`. Используется профиль `chrome`, который в этой закреплённой версии соответствует Chrome 152. HTTPX остаётся интерфейсом для обработки ответов и Cookie; TLS/HTTP-запросы Playerok выполняет libcurl из curl_cffi. Простая установка библиотеки поверх старой версии не включает новый транспорт — нужен этот выпуск бота.

## Что изменилось

- Новый транспорт используется в GraphQL и REST Playerok, проверке профиля, входе по почте и кнопке «Проверить доступ сервера».
- Для нового ввода по токену обновлён стандартный User-Agent. Уже сохранённые или введённые вручную Cookie и User-Agent не заменяются. Подключения и шифрование данных сохраняются.
- Другие поставщики, Telegram, GitHub и системный помощник обновления не переводятся на curl_cffi. Библиотека `playerokapi` не добавляется.
- Диагностический ZIP содержит название транспорта, профиль, версии curl_cffi/HTTPX и очищенные статусы последней анонимной проверки. Для старого результата транспорт отмечается неизвестным; после обновления кнопка делает новую проверку. Cookie, исходные ответы, заголовки и переписка не экспортируются.

## Поведение при ошибках

Сохраняются запрет перенаправлений, проверка сертификатов, доверенные CA и настройки прокси среды. Сетевые исключения libcurl преобразуются в прежние безопасные ошибки без URL, токенов и текста ответа.

Автоматические повторы curl_cffi отключены. Сбой после отправки мутации остаётся неопределённым результатом, который нельзя повторять вслепую. Для чтения сохраняется только прежняя однократная регистрация GraphQL-запроса при точном `PERSISTED_QUERY_NOT_FOUND`. HTTP 403/429 и прочие ошибки не запускают запасные транспорты или циклы запросов.

Cookie сохраняет один обработчик — HTTPX; отдельное хранилище Cookie curl_cffi выключено. Это сохраняет правила доменов/путей для входа по почте и не переносит Cookie между анонимными запросами диагностики. Сжатие декодируется один раз. Досрочное окончание ограниченного чтения закрывает сетевую передачу и возвращает соединение в пул.

## Проверки

- 266 автоматических тестов; линтер, форматирование, синтаксис shell и сборка wheel.
- Настоящий libcurl и локальный HTTP-сервер: передача Cookie/User-Agent, несколько Set-Cookie, gzip, JSON POST, запрет перенаправлений, ограниченное чтение и повторное использование клиента.
- Сетевые ошибки и HTTP 403/429/500: безопасные сообщения, отсутствие повторов, неопределённость мутаций. Сохраняются проверки входа, меню, склада, аренды, Stars/SMM и обновления.

Анонимные проверки из среды разработки вернули HTTP 403 HTML и с curl_cffi, и с HTTPX. Это не приёмка на VPS продавца и не проверка его токена. Живой вход, запросы к почте, покупки, сообщения покупателям, возвраты и развёртывание на сервере продавца не выполнялись. Устранение HTTP 403 на конкретном сервере не подтверждено. JavaScript, автоматическое решение CAPTCHA, ротация адресов и платные сервисы прохождения проверок не добавлены.

## Как обновить

В Telegram откройте **«Версия и обновления → Проверить сейчас → Обновить бота»**. Обычная установка с systemd сохранит настройки, сделает копию базы и перезапустится через существующий помощник протокола 1. Обновление с 0.3.0/0.4.x поддерживается; файлы помощника не меняются.

После обновления откройте **«Добавить аккаунт Playerok → Проверить доступ сервера»**, затем повторите подключение, если магазин ещё не добавлен. Если ошибка осталась, получите архив кнопкой **«Версия и обновления → Скачать диагностику»**. Не присылайте токен или Cookie в обсуждение GitHub.

Для ручной установки и Docker: [обслуживание установки](../INSTALLATION.md). Список зависимостей закреплён в `constraints.txt`; curl_cffi устанавливается обычным обновлением без отдельной команды администратора.
