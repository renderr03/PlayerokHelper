# Переход на PlayerokHelper 0.5.0

## Стабильная установка с systemd

В стандартной установке v0.3.0/v0.4.x на `main` используйте кнопку «Версия и обновления → Проверить сейчас → Обновить бота». Менеджер проверит рабочую копию, подготовит окружение, создаст копию базы и проверит запуск. Если текущие файлы изменены, сначала сохраните изменения: менеджер их не перезаписывает.

Существующие `.env`, ключ шифрования, `data` и `secrets` не удаляются. После успешного запуска новые подключения можно настраивать в [личном чате](CONNECTIONS.md). Уже действующие файлы подключения продолжают использоваться, пока вы не сохраните замену через панель.

## Ручной запуск или бета 0.5.0bN

Кнопка системного помощника не поддерживает установленную бета-версию. Остановите прежний рабочий процесс перед переходом. При ручном запуске завершите его в терминале; для службы:

```bash
sudo systemctl stop playerokhelper
```

Перейдите в свой каталог проекта. Сделайте защищённую копию данных и настроек, включая `.env`, `data` и `secrets` (последний каталог может отсутствовать). Если `DATA_DIR` изменён, копируйте именно его. Сохраните прежний код, если у вас есть собственные правки. Не меняйте `STOCK_ENCRYPTION_KEY`.

Для чистой Git-копии:

```bash
git fetch origin main
git switch main
git merge --ff-only origin/main
.venv/bin/python -m pip install -c constraints.txt .
```

Если локальной `main` ещё нет, `git switch main` создаст её по одноимённой удалённой ветке. Если Git сообщает о конфликте или расхождении, остановитесь и сохраните свои правки: не используйте принудительный сброс.

Запустите один процесс: `bash start.sh` для ручной установки либо `sudo systemctl start playerokhelper` для существующей службы. В меню проверьте номер 0.5.0 и подключение. Для отсутствующего системного менеджера его однократная установка описана в [INSTALLATION.md](INSTALLATION.md).

## Docker

Остановите старый контейнер и сохраните копию данных/настроек. Обновите чистую копию `main`, затем пересоберите образ и запустите контейнер с прежними томами, ключом шифрования и настройками. Используйте команды [Docker-раздела](INSTALLATION.md#docker). Два контейнера с одним Telegram-токеном или одной базой одновременно запускать нельзя.

## После перехода

Проверьте состояние подключения и свой тестовый лот. Ключи и сессии из панели сохраняются зашифрованно в SQLite и имеют приоритет над прежними файлами. Stars/SMM поставщики включаются отдельно после проверки баланса, курса и лимитов; обновление не включает их автоматически.

При неудачном запуске используйте журнал и порядок восстановления из [INSTALLATION.md](INSTALLATION.md). Не подставляйте старый ключ шифрования из другой установки и не удаляйте базу ради повторной настройки.
