# История изменений

## [0.6.2](docs/releases/v0.6.2.md) — 28 ноября 2026

- Обновляемая панель: переключатели сохраняют раздел, первый «Назад» возвращает в исходное меню, старые кнопки получают видимый ответ.
- Единые HTML-заголовки, эмодзи и акценты кнопок; русские статусы вместо внутренних кодов, понятные пустые списки и следующие действия при ошибках.
- Центр событий: приостановленные заказы, доставка сообщений, заказы поставщиков и списания без результата.
- Возврат проверяет реальный доступ к Playerok вместо устаревшей строки статуса; неопределённый запрос не повторяется.
- Stars/SMM выбирают свой лот из каталога; название подставляется автоматически.
- Все SMM-панели и Split автоматически загружают баланс после ввода ключа. Результат ручного обновления остаётся в карточке, включение поставщика само обновляет устаревшие данные.
- Исправлены страницы заказов и массовая настройка без выбранных лотов; добавлен обход интерфейса и регрессии финансовых операций.

## [0.6.1](docs/releases/v0.6.1.md) — 27 ноября 2026

- Добавлен VingBoost в меню SMM, настройки через консоль и совместимые шаблоны.
- Баланс и каталог VingBoost проверяются автоматически при сохранении ключа, без включения закупок.
- Учтены нативные типы простых услуг и статус Awaiting. Специальные услуги с дополнительными параметрами исключены.
- Отмена VingBoost отправляет order в единственном числе, проверяются подтверждения cancel/refill; неопределённые операции не повторяются.

- Калькулятор цены от себестоимости, календарь аренды, пакеты Stars и количество SMM кнопками.

- Раздельные RUB/USD KOSell, выбор валюты новых закупок и продлений, нативный учёт списаний.

## [0.5.6](docs/releases/v0.5.6.md) — 27 ноября 2026

- Исправлен сценарий из записи экрана: кнопка свежего уведомления открывает панель ниже события, если прежняя панель находится выше. Следующие кнопки и повторный вход из того же уведомления используют новое окно; само уведомление сохраняется.
- Главное меню собрано в компактные ряды. Обновлены страницы подключений, профиля, настройки, плагинов, управления и аналитики; общие сообщения получили HTML-заголовки, отступы и эмодзи.
- Нативные цвета кнопок: основные действия синие, подтверждения зелёные, отмена/возврат красные. Действия и протоколы кнопок сохраняются.
- Превью ссылок в ответах бота отключены. Из короткого описания релиза убраны отдельные ссылки отчёта, добавлена кнопка «Что нового»; подробный отчёт остаётся на GitHub.
- Форматирование и entities сохраняются при «Назад»; пользовательские данные экранируются, готовые HTML-карточки не форматируются повторно. Статус автоматизации различает выключенное состояние, паузу, ожидание связи и работу.

## [0.5.5](docs/releases/v0.5.5.md) — 25 ноября 2026

- Проверка тестового лота и привязка товара принимают обычные ссылки Playerok с коротким кодом и названием. Полный UUID определяется чтением `item(slug: ...)` через API; составлять UUID из короткого кода не требуется.
- До подтверждения проверяются владелец, полный ID и, для проверки скрытия, активный статус. Чужие/неактивные/удалённые товары и ошибки API показываются отдельно. Внешние URL не загружаются.
- Исправлено впечатление отсутствия ответа: неверная ссылка получает новый текст ошибки в том же окне; при поиске показывается ход проверки, затем название найденного товара.
- Подтверждение скрытия одноразовое, действует две минуты и связано с конкретным выбором. Новый ввод сбрасывает предыдущую кнопку. Старые кнопки прежних версий требуют повторного выбора товара.

## [0.5.4](docs/releases/v0.5.4.md) — 25 ноября 2026

- Подключение Playerok переведено на `curl_cffi 0.17.0` с профилем Chrome 152. Транспорт используется для GraphQL/REST, входа по почте и анонимной проверки доступа. Клиенты поставщиков и GitHub не меняются.
- Сохраняются Cookie/User-Agent, шифрование сессии, проверка TLS и сетевые настройки среды. Новые подключения по токену используют User-Agent Chrome 152; переданный вручную или ранее сохранённый User-Agent не заменяется.
- Нет автоматических повторов сетевых ошибок, HTTP 403/429/500 и мутаций. Сохраняется единственная регистрация отсутствующего GraphQL-запроса чтения. Перенаправления не выполняются.
- Диагностический ZIP дополнен версиями сетевых библиотек и очищенным результатом последней анонимной проверки. Проверка после смены транспорта выполняется заново.
- Добавлены проверки настоящего libcurl на локальном HTTP-сервере: сжатие, Cookie, тело POST, перенаправления и досрочное завершение чтения. Устранение HTTP 403 на VPS продавца не подтверждено.

## [0.5.3](docs/releases/v0.5.3.md) — 25 ноября 2026

- Пошаговый ввод полной сессии Playerok: Cookie, затем User-Agent того же браузера, без ручного JSON. Временный Cookie шифруется, ввод действует десять минут и очищается при навигации/отмене.
- Кнопка проверки доступа с сервера: два анонимных GET-запроса, без токенов, Cookie и авторизации; показ статусов сайта/API и признаков HTML-проверки. Проверка не чаще раза в минуту, без перехода по перенаправлениям.
- HTML-страница защиты при HTTP 403 отличена от JSON-отказа API. Ошибки входа по почте с HTTP 403 больше не предлагаются как ошибка кода из письма.
- Результат диагностики не определяет валидность токена и не доказывает блокировку IP. Обновление не гарантирует снятие отказа площадки; предусмотрена инструкция обычного доступа и подключения своей сессии.

## [0.5.2](docs/releases/v0.5.2.md) — 25 ноября 2026

- Меню, формы, ошибки ввода и переходы «Назад» редактируют одно сообщение. Если окно удалено или недоступно для редактирования, создаётся замена; неопределённый сетевой сбой не запускает дублирующую отправку.
- Уведомления сохраняются в истории отдельно от панели. Их кнопки открывают действующую панель; после перезапуска окно создаётся при первом переходе из карточки.

- Подтверждение выполнения доступно после выдачи, возврат использует прежний диалог с подтверждением и свежей проверкой. Новых платных действий оформление не добавляет.

Сохраняется исправление подключения Playerok из 0.5.1. [Подробный отчёт](docs/releases/v0.5.2.md).

## [0.4.0](docs/releases/v0.4.0.md) — 23 ноября 2026

### Новые возможности

- 🎮 Собственный пул аренды: зашифрованные реквизиты, резерв за заказом, сроки, напоминания, платные продления и обязательное подтверждение смены доступа перед повторной выдачей. Запрос Guard передаётся продавцу.
- 🎁 Бонусы за каждые N завершённых покупок после включения программы: отдельный склад, команда `!бонус`, защита от повторной выдачи и расходы в аналитике. Спорные отправки удерживаются до сверки.
- 💬 `/inbox`: новые в панели и ожидающие ответа чаты, проблемные заказы, история за 30 дней и именованные быстрые ответы с предпросмотром.
- 📦 Поиск по всему каталогу, страницы, фильтры и массовые настройки до 200 лотов с предпросмотром и пропуском изменившихся строк.
- 💰 Настраиваемый порог ожидаемой маржи по лоту. Уведомления выключены по умолчанию; цены и закупки автоматически не изменяются.

### Улучшено

- Независимые расписания заказов, чатов, каталога и отправок; ограничение параллельных GraphQL-запросов, пауза после 429 и задержки после ошибок.
- Этапы установки, проверка зависимостей и свободного места, таймауты загрузки и проверка Telegram-подключения перед установкой службы.
- Статус обновления, проверка места перед запуском, диагностический ZIP из разрешённых полей. Очистка завершённых обновлений сохраняет три последних комплекта и защищает используемые окружения.

### Совместимость

- Аддитивная миграция SQLite сохраняет прежние лоты, заказы, склад и ключ. Совместимо с установленным менеджером обновлений v0.3.0: переход через `/version` без замены системного помощника.
- Бонусная программа включается отдельно. Срок собственной аренды начинается с резерва; завершение срока не отзывает доступ к внешнему аккаунту автоматически.

- Релиз привязан к точному коммиту; изменение тега останавливает обновление. Предрелизы не предлагаются.
- Повторные запросы и устаревшие кнопки отклоняются. Локальные изменения проекта не перезаписываются обновлятором.
- При проверке запуска остановлены обработка заказов, восстановление бизнес-операций и команды изменения настроек. Подтверждаются версия, процесс службы и два свежих сигнала запуска после проверки Telegram-подключения.
- Сборка, pip и операции с файлами выполняются от пользователя установки. Менеджер systemd управляет только службой PlayerokHelper; его код устанавливается один раз из консоли.

### Переход с предыдущих версий

Один раз запустите обычный установщик от прежнего пользователя сервера. Он установит службу и наблюдатель обновлений. После этого совместимые стабильные версии доступны из Telegram. Настройки, ключ шифрования, склад и прежние функции сохраняются.
